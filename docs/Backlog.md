## HTTP 타임아웃 값을 실측 기반으로 재설정

- **현재 값**: connect 2s / read 5s (`application.yml`) — 이전 프로젝트에서 계승한 값일 뿐, 근거 데이터 없음
- **할 일**: 외부 호출(공단 acsCtrList, 추후 OpenWeatherMap)의 응답 시간을 로그로 수집하고,
  충분한 표본이 쌓이면 p99 기준 + 여유분으로 타임아웃을 재설정한다
- **측정 방법 후보**: RestClient 호출 전후 시간 기록(간단 로깅 인터셉터), 이후 로그에서 분포 집계
- **판단 기준**: 타임아웃이 p99보다 지나치게 크면 장애 시 스레드가 오래 물리고,
  p99에 너무 붙으면 정상 요청이 타임아웃으로 잘림 — 그 사이의 트레이드오프를 실측으로 정한다
